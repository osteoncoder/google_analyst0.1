App Ecosystem Intelligence

A live view over the cleaned dataset — ratings, reported installs, size and category dynamics, plus two machine-learning models trained with scikit-learn.

— records ·

01App Quality Benchmark

Size (MB) vs. user rating, bubble area ∝ reported installs (band lower bound) — apps with ≥1,000 reported installs and known size/rating only.

02Feature Correlation

Pearson correlation matrix over the genuine numeric columns of the cleaned dataset — Reviews and Installs are log1p-transformed (heavy right skew). The dataset contains no location column, so the original map was removed. Correlation is association, not causation.

03Apps by Last-Updated Month

Apps grouped by the month of their latest update and category. This is a snapshot distribution of each app’s most recent update date — not a complete update history and not a monthly install history.

04Rating Distribution

Histogram of app ratings (all apps with a valid 1–5 rating), bin width 0.25. The original “cumulative installs” growth curve was a fixed multipliers projection with no date data behind it, so it was replaced by this directly observed distribution.

05Category Analysis

One point per category: total review volume (x, log scale, zero-safe) vs. average rating (y). Averages are the unweighted mean of the category’s app ratings; totals are sums of review counts. Ratings and review counts no longer share one axis.

06Pricing Mix

Free vs. paid app counts (and mean listed price where a Price column exists). Listed price is a price tag, not observed revenue — no revenue is estimated anywhere in this dashboard. Legitimate $0.00 prices are preserved, never imputed.

07Rating Predictor

M1 regression: app profile (category, size, price, review volume) → expected average rating. Inference uses the saved scikit-learn preprocessing + model pipeline — nothing is retrained per request. It runs on the FastAPI backend when app.py is serving, and otherwise in this page via ml_inference.js (the same pipeline exported to ml/artifacts/browser/models.js); the result always says which one answered. The form asks for only what a user can know; the model's other inputs (content rating, app age, time since the last update, developer portfolio size…) are imputed to their training medians, and every imputation is listed with the value used.

08Install-Tier Classifier

M2 four-class classifier (primary version excludes Reviews, a strong proxy for installs). Inputs available at prediction time: category, size, price, content rating, minimum Android, and the ad / in-app-purchase / Editors' Choice flags. App age, days since last update and developer portfolio size are imputed to their training medians — every imputation is stated, with the value used, under the result. Probabilities are model estimates, not guarantees. Like section 07, this works with or without the Python backend.

App age, days since last update and developer portfolio size have no field here — they are imputed to their training medians, and every imputation is listed with the result.

Dataset, split & limitations

Data note — dataset: loading…. Primary source: the MIT-licensed gauthamp10/Google-Playstore-Dataset scrape (June 2021, 24 attributes); the committed default is a deterministic stratified sample and python fetch_dataset.py builds the full 2,312,944-row file (data/raw/playstore_full.csv, auto-detected by clean.py). Cleaning follows the documented rules in clean.py (install bands treated as lower bounds, zero prices preserved, one category typo fixed, exact duplicates removed). ML: scikit-learn pipelines, seed 42, grouped train/test split; models are trained by python train_models.py and served by python app.py (no retraining per request). No revenue, geography, or historical trends are fabricated anywhere on this page.
