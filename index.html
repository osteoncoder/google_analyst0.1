01App Quality Benchmark

Size (MB) vs. user rating; bubble area ∝ reported installs.

Method & caveats
Installs are a band lower bound, not an exact download count — the bubble area is therefore a floor, not a measured volume. Only apps with ≥1,000 reported installs and a known size and rating are plotted.

Each bubble is one app. Colour groups apps by category (48 of them — a legend that long is unreadable, so hover any bubble for its name, category and install band).

02Feature Correlation

Pearson correlation over the genuine numeric columns. Correlation is association, not causation.

Method & caveats
Reviews and Installs are log1p-transformed (heavy right skew). The dataset contains no location column, so the original choropleth map was removed rather than drawn from invented geography.

03Apps by Last-Updated Month

Apps grouped by the month of their latest update and category.

What this does not claim
A snapshot distribution of each app’s most recent update date — not a complete update history and not a monthly install history. Only rows whose Last Updated field parsed to a real date are counted.

04Rating Distribution

Histogram of app ratings (1–5), bin width 0.25.

Why this replaced the growth curve
The original “cumulative installs” chart was a fixed-multipliers projection with no date data behind it. This is a directly observed distribution instead. Apps whose rating is missing (unrated listings) are excluded, never counted as 0.

05Category Analysis

One point per category: total review volume (x, log scale) vs. average rating (y).

Method & caveats
Averages are the unweighted mean of the category’s app ratings; totals are sums of review counts. Ratings and review counts no longer share one axis (the original did, which made the two incomparable scales look related). Categories with zero total reviews are excluded from the log axis.

06Pricing Mix

Free vs. paid app counts, and mean listed price.

Method & caveats
Listed price is a price tag, not observed revenue — no revenue is estimated anywhere in this dashboard. Legitimate $0.00 prices are preserved, never imputed to a non-zero value, and a dataset with no Price column at all is reported as unknown rather than assumed to be all-free.

07Rating Predictor

M1 regression: app profile → expected average rating. Runs on the FastAPI backend when app.py is serving, otherwise in this page via ml_inference.js — the result always says which one answered.

How inference works & what is assumed
Inference uses the saved scikit-learn preprocessing + model pipeline — nothing is retrained per request. The form asks for only what a user can know; the model's other inputs (content rating, app age, time since the last update, developer portfolio size) are imputed to their training medians, and every imputation is listed with the value used under the result. Predicted ratings are clipped to the rating domain [1, 5] and say so when clipped.

08Install-Tier Classifier

M2 four-class classifier. The primary version excludes Reviews, a strong proxy for installs. Probabilities are model estimates, not guarantees.

Inputs & what is assumed
Inputs at prediction time: category, size, price, content rating, minimum Android, and the ad / in-app-purchase / Editors' Choice flags. App age, days since the last update and developer portfolio size have no field here, so they are imputed to their training medians — every imputation is stated, with the value used, under the result. Like section 07, this works with or without the Python backend.

09Model Performance

Actual evaluation metrics from the reproducible training run. No tuned-to-test numbers, no placeholders.

Protocol
Fixed seed; 80/20 train/test split grouped by app name and made before any preprocessing; 75/25 train/validation for model selection; the winner is refit and the test set is used exactly once. Any candidate whose serialized pipeline exceeds the 10 MB shipping budget is excluded and shown struck out.

Dataset, split & limitations

Data note — loading…. Cleaning and modelling follow the documented rules in clean.py and train_models.py. No revenue, geography or historical trend is fabricated anywhere on this page.
Provenance & pipeline
Primary source: the MIT-licensed gauthamp10/Google-Playstore-Dataset scrape (June 2021, 24 attributes). The committed default is a deterministic stratified sample; python fetch_dataset.py builds the full 2,312,944-row file (data/raw/playstore_full.csv), which clean.py auto-detects. Cleaning treats install bands as lower bounds, preserves $0 prices, fixes one category typo and removes exact duplicates. ML: scikit-learn pipelines, seed 42, grouped train/test split; models are trained by python train_models.py and served by python app.py (no retraining per request).
